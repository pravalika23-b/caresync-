Requirements Engineering

Functional & Non-Functional Requirements

Functional Requirements

  • • User Authentication: Multi-role registration & login (Patient, Doctor, Admin) via JWT.
  • • Dynamic Slot Generator: Generates 15-min intervals excluding leaves & booked slots.
  • • Anti-Double-Booking Engine: Atomic lock blocks simultaneous duplicate bookings (409 Conflict).
  • • Live Queue Engine: Assigns daily token, triggers check-in, and tracks serving sequence.
  • • Doctor Clinical Console: One-click "Call Next Patient" broadcasts instant alert to patient.
  • • Digital E-Prescriptions: Captures diagnoses, clinical advice, and itemized multi-line Rx drugs.
  • • Machine Learning Intelligence: Predicts duration & appointment no-show probability.

Non-Functional Requirements

  • • Low Latency: REST API response time < 200ms; WebSocket broadcasts < 50ms.
  • • Concurrency: Non-blocking Node.js event loop handles 1,000+ concurrent requests.
  • • Robust Security: Passwords hashed with bcrypt (10 rounds); stateless JWT verification.
  • • High Usability: Mobile-first responsive UI built with Tailwind CSS.
  • • Data Integrity: Compound uniqueness indexes on (doctor_id, date, time).
  • • Maintainability: Modular MVC pattern with centralized error interceptors.

Backend

Backend Architecture & Controller Logic

Security & RBAC

• bcryptjs: 10 salt rounds for irreversible password hashing.

• JWT Tokens: Signed with 7-day expiration and user payload.

• authorize() Middleware: Restricts endpoints to authorized roles.

Concurrency Control

• Atomic database transactions (tx.query).

• Verifies slot emptiness immediately before insert.

• Unique compound constraint blocks race conditions.

WebSocket Broadcasts

• Scoped rooms isolate doctor and patient updates.

• emitQueueUpdate broadcasts on call/complete.

• emitPatientAlert triggers personal chime alert.

Backend Directory Structure: server/src/ partitioned cleanly into config/, controllers/, middleware/, routes/, services/, and database/.
Database

Database Integration & Dual-Driver Strategy

Dual-Driver Implementation

• Zero-Config Local Development: Built-in Node SQLite driver (hospital.db) with WAL journal mode allows instant local cloning without running a MySQL/Mongo daemon.

• Production Deployment: Toggled via DB_CLIENT=mysql or MongoDB Mongoose adapter for cloud databases (AWS RDS, PlanetScale, MongoDB Atlas).

• Automated Migrations: migrate.js automatically provisions all schemas with foreign key cascades.

Indexing & Concurrency Protection

• Compound Slot Index: UNIQUE(doctor_id, appointment_date, appointment_time) ensures zero slot collisions at storage engine level.

• Fast Queue Lookups: Indexes on doctor_id and queue_date for sub-millisecond wait time and ahead calculations.

• Automated Seeding: seed.js pre-populates 7 departments, 5 doctors, schedules, patients, queue entries, and demo accounts.

Problem Solving

Engineering Challenges & Adopted Solutions

Challenge 1: Double-Booking Race Conditions

Two patients booking the exact same slot at the exact same millisecond.

Solution: Atomic transaction lock + compound unique constraint (doctor_id, date, time). Conflict returns 409.

Challenge 2: Real-time Multi-Device Sync

Patients repeatedly refreshing browsers causing lobby frustration & server load.

Solution: Socket.IO scoped rooms broadcast instant token advances without page reload.

Challenge 3: Inaccurate Static Wait Estimates

Static 15-min constant ignores patient age, visit type, and symptom complexity.

Solution: Machine learning regression model predicting duration based on clinical features.

Challenge 4: CORS Errors & Session Expiry

Port 5173 to 5000 CORS rejections and unhandled JWT token expirations.

Solution: Express CORS credentials middleware + Axios response interceptors handling 401.
